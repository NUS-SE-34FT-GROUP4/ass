# AWS infrastructure (Terraform)

```
bootstrap/   S3 state bucket, DynamoDB lock table, budget alarm. Once per account, local state.
shared/      ECR repositories (core, search, chat) and the GitHub OIDC provider. Once per account.
env/         One environment. Workspaces: staging, production.
../scripts/  run-sql.sh: run a SQL file against RDS from inside the VPC.
```

## What env/ creates

```
                    CloudFront (HTTPS, default *.cloudfront.net certificate)
   /* (Vue SPA) -> S3 frontend    /media/* -> S3 media    /api/*, /ws/* -> ALB
                                                                  |
              ALB (public subnets, accepts CloudFront only)       |
     /api/search/* -> search      /ws/* -> chat      anything else -> core
                                                                  |
        ECS Fargate services (private subnets): core, search, chat
                                                                  |
   RDS MySQL | ElastiCache Redis (TLS) | OpenSearch | RabbitMQ | Secrets Manager
```

| | staging | production |
|---|---|---|
| ECS tasks | 1 per service, one AZ | 1 to 4 per service, two AZs, target tracking |
| RDS MySQL | single-AZ, no backups | Multi-AZ, 7-day backups, deletion protection |
| OpenSearch | 1 node | 2 nodes, one per AZ |
| RabbitMQ | Amazon MQ (or the container fallback) | Amazon MQ |
| GitHub role trusts | `main` and Environment `staging` | Environment `production` only |

Every service validates JWTs itself with the key in `<env>/jwt`. Database,
broker and JWT credentials are generated by Terraform or RDS, kept in Secrets
Manager and injected by ECS; none are in the repository or in task environment
variables.

## First time on a new account

```bash
cd infra/terraform/bootstrap
terraform init
terraform apply -var alert_email=you@example.com   # writes ../env/backend.hcl

cd ../shared
terraform init -backend-config=../env/backend.hcl -backend-config="key=c2csectrade/shared.tfstate"
terraform apply

cd ../env
terraform init -backend-config=backend.hcl
terraform workspace new staging
terraform apply
```

## Bringing staging up

1. Push an image to each ECR repository (CI does this; until Search and Chat
   are extracted, push the current application image to all three). Services
   whose image is not there yet can be held at `desired_count = 0`.
2. `terraform apply` in the `staging` workspace.
3. Load the schema and seed data:
   `infra/scripts/run-sql.sh staging init.sql`
4. When the WP8 grant script is ready, run it the same way, then set
   `db_use_master_user = false` and apply. Its users must be named `core_svc`
   and `chat_svc` with the passwords in `<env>/db/core` and `<env>/db/chat`.
5. Upload the frontend build to the `frontend_bucket` output and open `app_url`.

## Day to day

```bash
cd infra/terraform/env
terraform workspace select staging        # or production
terraform plan
terraform apply
terraform destroy                          # staging, when nobody is using it
```

CI owns the task definition revision (new image tag per deploy) and auto-scaling
owns the task count, so Terraform ignores both after creation.

## RabbitMQ

Search indexing and Chat cross-instance delivery both run through RabbitMQ, so
every environment has one. Both workspaces use Amazon MQ by default. To save
money, staging can run `rabbitmq:3.12-management` on ECS instead:

```bash
terraform apply -var rabbitmq_mode=container      # staging only; production refuses
```

The services find it at `rabbitmq.c2csectrade-staging.internal:5672` without
TLS; queued messages are lost if the task restarts. Credentials are in
`<env>/rabbitmq` either way.

## Notes for the service owners

- **Redis** requires TLS: the task sets `SPRING_DATA_REDIS_SSL_ENABLED=true`.
- **OpenSearch** is reached at `SPRING_ELASTICSEARCH_URIS` (HTTPS, no request
  signing; the security group is the gate). The Elasticsearch 8 Java client
  checks for an `X-Elastic-Product` header that OpenSearch does not send, so
  the Search Service should use the OpenSearch client or the REST client.
- **Media**: `MINIO_ENDPOINT` points at S3 and `MINIO_BUCKETNAME` at the media
  bucket. There are no access keys: the client must use the task role (for
  MinIO, `IamAwsProvider`). Store objects under `media/` and build public URLs
  from `MEDIA_PUBLIC_BASE_URL`.
- **Database**: `SPRING_DATASOURCE_URL` uses `sslMode=REQUIRED`.

## Cost (ap-southeast-1, on-demand, approximate)

| Item | USD/hour |
|---|---|
| Amazon MQ mq.m7g.medium | 0.17 |
| Fargate, 3 tasks of 0.5 vCPU / 1 GB | 0.09 |
| NAT gateway | 0.06 |
| OpenSearch t3.small.search, per node | 0.06 |
| RDS db.t4g.micro (x2 for Multi-AZ) | 0.03 |
| ElastiCache cache.t4g.micro | 0.02 |
| ALB | 0.03 |
| Public IPv4 addresses | 0.015 |

Staging is about USD 0.47 an hour (about 11 a day), or 0.33 with the RabbitMQ
container. Production starts around USD 0.60 an hour and grows with scaling.
Everything is billed by the hour whether used or not: destroy staging when
idle, and bring production up only for the load test and the presentation.

bootstrap/ keeps its own state locally (bootstrap/terraform.tfstate, not
committed), since it creates the bucket remote state lives in. Its budget
emails when usage passes USD 10 in a month, counting usage before credits.
